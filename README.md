# フリマップ（仮）

## 1. サービス概要

このサービスは、フリーマーケットなどのイベント情報を地図上で探せるサービスです。
ユーザーは、開催場所や住所を地図上のマーカーから確認でき、マーカーをクリックすることでイベント名や住所などの詳細情報を確認できます。
イベント情報を地図上で開催場所を直感的に把握できることを目的としています。



## 2. 開発背景

私は休日によくフリーマーケットへ出かけるのですが、情報はSNSやイベントサイトで見つけることができますが、そのたびイベントページに書かれた住所をマップで開いて確認していました。
そのため、開催場所を地図上で一覧できれば、もっと直感的にイベントを探せるのではないかとそんな日頃の小さな不便が、このサービスを作ろうと思ったきっかけです。

---

## 3. 課題の整理

フリマは最近人気になっており、来客者も主催者もかなり増えているため
開催しているイベントや開催日をまとめているサイトも多くなっているが
実際に、開催地を **手軽に** 把握できるものがない

### 3-2. 本当に解決したい課題は何か

- **なぜ？** → 需要が上昇しているため、情報を網羅するためにリストで表示しているものがほとんどのため
- **なぜ？** → Google Mapsで「フリマ」と検索しても検索に引っかからないため
- **なぜ？** → イベントを調べた後にマップアプリに移行して場所を調べるという手間があるため

**→ 本当に解決したい課題：フリマに行きたい人が、開催地を調べたいのだが、フリマのみが表示されているという地図アプリがないため調べる手間がかかる**

---

## 4. 想定ユーザー

**ターゲット：**

- フリマに行きたい人: 手軽に開催地を把握する方法ができれば、新しいフリマを発見することや初めてのフリマ来客の一歩に貢献できる。
- フリマ出店者のほとんどが元は来客者であるため、主催者側としては出店者の応募掲示板としても利用することができる。

**環境設定：**

- 環境：スマートフォン・タブレット・PC、ブラウザがあれば使える
- 理由：フリマを調べる際にはアプリを調べるのではなく、ブラウザで「フリマ　開催地」などと調べるケースが多いため、モバイルアプリでなくwebアプリである需要がある。

### 4-2. 自分とユーザーの距離

**→ 自分自身と、同じ趣味を持つ友人**

イベントを探す際には、SNSやイベントサイトで情報を見つけても、開催場所を確認するためにGoogle Mapsで住所を検索し直す必要があり、不便さを感じていました。
また、フリーマーケットへ一緒に行く友人からも、「イベント情報を見落としてしまうことがある」「場所を調べるのが面倒で、気になっていても行かないことがある」という声を聞く。

### 4-3. 実際に使われる可能性について

- **最初に使ってくれそうな人：** 最初に使ってくれる人は主催者側の登録
- **どんな場面で思い出すか：** フリマに行きたいという思う時、フリマを開催しようとする時
- **置き換えてまで使う理由：** フリマに行きたい人が、フリマだけ表示されている地図を見れるということ

### 4-4. ユーザーがサービスを導入して利用するまでのイメージ

1. フリマ主催者は出店者を常に応募しているため、主催者にこのように開催を宣伝できるアプリがあると、メール等でコンタクトを取る
2. 登録されているピンが増えていくことで、主催者も徐々に登録を進めていく
3. マップが充実されていき、来客側も地図から探しやすくなる
4. 来客者が増え、主催者も登録するメリットがあるとマップが充実していくという循環が起きる

## 5. 既存サービス・競合調査
### 5-1. 似たサービスの調査

#### サービス名：フリーマーケット・マルシェ・クラフトフェア・蚤の市ガイド　<br>
URL [https://www.asken.jp/](https://fmfm.jp/)
- 主なターゲット
  - フリーマーケット・マルシェ・クラフトフェア・蚤の市に興味がある人、今回のアプリとターゲットは同じである
- 強み<br>

- 弱み・物足りなさ
  - 期間やエリアを絞ってで調べることはできるのだが、リストで表示されるので、どこらへんで開催されているイメージがつきずらい

<br>

#### サービス名：Wakerplus<br>
URL [https://menew.jp/](https://www.walkerplus.com/)
- 主なターゲット
  - イベント好き
- 強み<br>
  - フリーマーケットだけではなく、花火大会や音楽イベントなど、多々のイベントを調べることができる。<br>
- 弱み・物足りなさ
  - 情報が膨大なので、すでに目星がついてるイベントを深堀りするなどが利用方法であるため、手軽さはあまりなく旅行サイトに近いイメージ。

<br>



### 5-2. 自分のアプリが違う点

マップで開催地がひと目で分かる、「テキスト」メインのアプリが多い中、感覚的に「あ、ここでやってんじゃん行こー」とわかりやすいアプリである。
食事を例にあげるが、事前に場所を決めていない場合、お腹が空き外でご飯屋を決める際には
事前に決めようとしない限りは、お店が掲載されているアプリで住所を確認し、マップアプリに移行して場所を調べるという手間は行わず、直接マップアプリで調べることが多いと考える。

### 5-3. 差別化を一文で決める

**「フリマを探す」と「場所を調べる」を一つの体験として提供することで、フリマを地図上から直感的に見つけられる点が、本サービスの特徴**
——これが既存サービスにはない、このアプリだけの価値になる。

このサービスを使うことで、ユーザーは以下のように変化します。

#### 行動の変化
- フリマを探す手間が減ること。知らなかったフリマに出会い、新しい発見ができる。

#### 考え方の変化

## 8. このアプリの懸念点とその対策

### 懸念点①：　MVPリリース直後の需要

- **何が問題になりそうか：** MVPリリース直後のデータ量が少なく、アプリとしての完成度がかなり低いため、来客ユーザーにとっては利用するに値しないアプリになっている。
- **なぜそう思うか：** ユーザー(主催者)にイベントの登録をお願いしているので、MVPリリース直後のデータは0であるため
- **対策：** その他のフリマが掲載されているアプリを確認したのだが、アプリの大中小は関係なく
  主催者側としてはどのような形であっても無料で掲載できるものであれば、出店者を集めたいという思いで投稿を行っているため、こちら側からメール等でコンタクトをとれば少しずつだが登録されていくと考えている。

### 懸念点②：不適切な内容の投稿

- **何が問題になりそうか：** 不適切な投稿が表示されると信頼を失う
- **なぜそう思うか：** 悪意ある内容が投稿される可能性があるため
- **対策：** 文字制限など投稿のフィルターを将来的には実装予定

## 技術検証（Google Maps API）
地図機能は本アプリの中核となるため、実装前にテスト用リポジトリを作成し、Google Maps APIおよび関連技術の動作検証を行った。

### 1. 地図の表示
まずはGoogle Maps JavaScript APIの公式ドキュメントを参考に、地図が正常に表示されるかを検証した。

```html
<gmp-map
  center="35.65861,139.70111"
  zoom="13"
  map-id="DEMO_MAP_ID">
  <gmp-advanced-marker
    position="35.65861,139.70111"
    title="渋谷駅">
  </gmp-advanced-marker>
</gmp-map>
```

座標を変更することで、任意の位置へ地図を表示し、マーカーを配置できることを確認した。

---

### 2. 住所から緯度・経度を取得する仕組み
イベント情報を地図へ表示するため、住所から緯度・経度を取得する仕組みを検証した。
まず、イベント名・住所・緯度・経度を持つテスト用モデルを作成し、住所のみを登録するフォームを作成した。この時点では、緯度・経度は`nil`で保存されることを確認した。
続いて、Geocoderを導入し、モデルへ以下の設定を追加した。

```ruby
geocoded_by :address
after_validation :geocode
```

また、Railsコンソールでも動作を確認した。

```ruby
results = Geocoder.search("渋谷駅")
results.first.coordinates
#=> [35.658..., 139.701...]
```

検証中には、

```
Google API error:
request denied (API keys with referer restrictions cannot be used with this API.)
```

というエラーが発生した。
原因を調査したところ、Google Geocoding APIで利用するAPIキーの制限設定が原因であったため、適切な設定へ変更することで住所から緯度・経度が自動で保存されることを確認した。

---

### 3. 地図上へイベントを表示
取得した緯度・経度をGoogle Maps JavaScript APIへ渡し、イベントの位置へマーカーを表示する検証を行った。

```javascript
const marker = new google.maps.Marker({
  position: {
    lat: event.latitude,
    lng: event.longitude
  },
  map: map
});
```

イベントごとに緯度・経度を渡すことで、複数のイベントを地図上へ表示できることを確認した。

---

### 4. マーカークリック時の情報表示
マーカーにクリックイベントを追加し、イベント情報を表示する機能を検証した。

```javascript
marker.addListener("click", () => {
  infoWindow.open({
    map: map,
    anchor: marker
  });
});
```

クリック時にInfoWindowが表示され、イベント名などの情報を確認できることを検証した。

---

* Google Geocoding APIとGeocoderを利用した住所から緯度・経度への変換
* 登録したイベント情報を地図上へ表示する仕組み

# フリマップ

## 1. サービス概要

このサービスは、フリーマーケットなどのイベント情報を地図上で探せるサービスです。
ユーザーは、開催場所や住所を地図上のマーカーから確認でき、マーカーをクリックすることでイベント名や住所などの詳細情報を確認できます。
イベント情報を地図上で確認し、開催場所を直感的に把握できることを目的としています。

---

## 2. 開発背景

私は休日によくフリーマーケットへ出かけるのですが、情報はSNSやイベントサイトで見つけることができますが、そのたびにイベントページに書かれた住所をマップで開いて確認していました。
そのため、開催場所を地図上で一覧できれば、もっと直感的にイベントを探せるのではないかと考えました。そんな日頃の小さな不便が、このサービスを作ろうと思ったきっかけです。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

フリマは最近人気になっており、来客者も主催者もかなり増えているため、
開催しているイベントや開催日をまとめているサイトも多くなっているが、
実際に開催地を **手軽に** 把握できるものがない。

### 3-2. 本当に解決したい課題は何か

- **なぜ？**
  → フリーマーケットへの関心が高まり、開催されるイベントや掲載情報が増えているため

- **なぜ？**
  → 既存のイベント情報サービスは一覧やテキスト中心のものが多く、開催場所を地図上で直感的に把握しにくいため

- **なぜ？**
  → Google Mapsで「フリマ」などと検索しても、開催予定のフリーマーケット情報を十分に見つけられないため

- **なぜ？**
  → 気になるイベントをイベントサイトなどで見つけたあと、住所を確認し、Google Mapsで開催場所を検索し直す必要があるため

**→ 本当に解決したい課題：  
フリーマーケットへ行きたい人が、イベント情報と開催場所を別々に調べる必要があり、「フリマを探す」と「場所を調べる」が分断されていること。**

## 4. 想定ユーザー

年齢や職業ではなく、フリーマーケットへの関わり方や、イベントを探すときの行動を基準にユーザーを想定しています。

### 4-1. メインユーザー

SNSやメディアなどをきっかけに一度フリーマーケットへ行き、
「またフリマに行きたい」と思うようになった人をメインユーザーとして想定しています。

初めてフリーマーケットへ行く場合は、SNSで流れてきた投稿やメディアで紹介されたイベントなど、すでに行き先が決まった状態で参加することが多いと考えています。

一方で、一度フリーマーケットに興味を持ったあとに再び行こうとすると、

- 今週末に開催されるフリマはないか
- 自分の近くで開催されているフリマはないか
- 今まで知らなかったフリマはないか

と、自分からイベントを探す必要があります。

現在は、SNSやイベントサイトなどから開催情報を探し、気になるイベントを見つけたあと、住所をGoogle Mapsで検索して開催場所を確認する必要があります。

フリマップでは、開催情報と開催場所を最初から地図上で確認できるようにすることで、
「フリマを探す」と「場所を調べる」を一つの体験にし、次に行くフリーマーケットをより手軽に見つけられるようにします。

### 4-2. その他の想定ユーザー

- **フリーマーケットの主催者**
  - 開催情報を掲載し、来場者や出店希望者にイベントを知ってもらいたい人

- **フリーマーケットへの出店希望者**
  - 地図からフリーマーケットの開催情報を知り、出店先を探すきっかけにしたい人

また、すでにフリーマーケットによく行く人にとっても、
SNSやイベントサイト、地図アプリを行き来する既存の探し方より、
少ない手順で開催情報を確認できるサービスを目指しています。

### 4-3. 自分とユーザーの距離

**→ 自分自身と、同じ趣味を持つ友人**

イベントを探す際には、SNSやイベントサイトで情報を見つけても、開催場所を確認するためにGoogle Mapsで住所を検索し直す必要があり、不便さを感じていました。

また、フリーマーケットへ一緒に行く友人からも、
「イベント情報を見落としてしまうことがある」
「場所を調べるのが面倒で、気になっていても行かないことがある」
という声を聞いています。

### 4-4. 実際に使われる可能性について

- **最初に使ってくれそうな人：**
  複数のイベント掲載サイトへ同じ開催情報を個別に登録してでも、来場者や出店者との接点を増やそうとしている小規模なフリーマーケットの主催者を想定しています。

  まずはそのような主催者へこちらから直接アプローチし、最初の1件を掲載してもらうことを目指します。

- **どんな場面で思い出すか：**
  来場者は「またフリマに行きたい」「今週末どこかで開催されていないか」「近くで開催されているフリマはないか」と思ったとき。
  主催者は、新しくイベントを開催し、来場者や出店者へ開催情報を告知したいとき。

- **置き換えてまで使う理由：**
  来場者は、SNSやイベントサイトでイベントを探したあとに別の地図アプリで住所を検索する必要がなく、フリマップ上で開催場所を見ながらイベントを探せるため。
  主催者にとっても、来場者や出店者へ情報を届けるための新しい告知先として利用できるため。

### 4-5. ユーザーがサービスを導入して利用するまでのイメージ

1. 来場者や出店者との接点を増やすため、複数のイベント掲載サイトを利用している小規模な主催者へ、こちらからフリマップを案内する
2. 主催者にイベントを登録してもらい、地図上に開催情報が掲載されている状態を作る
3. 来場者が地図からフリーマーケットを探せるようになる
4. 来場者や出店希望者が増えることで、主催者側にもイベントを掲載するメリットが生まれる
5. 掲載する主催者が増え、さらに地図上の情報が充実していく循環を目指す

### 5-2. 自分のアプリが違う点

マップで開催地がひと目で分かる。「テキスト」メインのアプリが多い中、感覚的に「あ、ここでやってる、行こう」と分かりやすいアプリである。

食事を例に挙げるが、事前に場所を決めていない場合、お腹が空き外でご飯屋を決める際には、事前に決めようとしない限り、お店が掲載されているアプリで住所を確認し、マップアプリに移行して場所を調べるという手間は行わず、直接マップアプリで調べることが多いと考える。

### 5-3. 差別化を一文で決める

**「フリマを探す」と「場所を調べる」を一つの体験として提供することで、フリマを地図上から直感的に見つけられる点が、本サービスの特徴**

——これが既存サービスにはない、このアプリだけの価値になる。

## 8. このアプリの懸念点とその対策

### 懸念点①：MVPリリース直後は掲載イベントが0件である

- **何が問題になりそうか：**
  フリマップは、主催者がイベントを登録することで地図上に開催情報が表示される仕組みのため、MVPリリース直後は掲載イベントが0件の状態から始まる。

  イベントが0件では、一般ユーザーがサービスを利用する理由がなく、利用者が増えにくい。

  一方で、一般ユーザーがいないサービスには、主催者側もイベントを掲載するメリットを感じにくい。

  そのため、

  **掲載イベントが0件**
  → **一般ユーザーが増えない**
  → **主催者が投稿するメリットを感じにくい**
  → **掲載イベントが増えない**

  という悪循環が起こる可能性がある。

- **なぜそう思うか：**
  フリマップは、主催者がイベントを掲載し、その情報を一般ユーザーが地図から探すことで価値が生まれるサービスである。

  そのため、サービス初期にイベントが掲載されている状態を作れなければ、一般ユーザーにも主催者にも利用するメリットが生まれにくいと考えている。

- **対策：**
  サービス公開直後から自然に主催者が登録してくれることを待つのではなく、こちらから主催者へ直接アプローチする。

  特に、複数のイベント掲載サイトへ同じ開催情報を個別に登録してでも、来場者や出店者との接点を増やそうとしている小規模なフリーマーケットの主催者を中心に声をかける。

  サービス公開から2週間を目安に、約50件の主催者へメールやSNSで連絡し、まずは1件以上のイベント掲載につなげることを目標とする。

  アプローチの中で、主催者から意見や掲載を断る理由をいただいた場合は、その内容をもとにサービスや案内方法を改善する。

  それらの改善を行った上でも、約50件の主催者すべてから掲載を断られた場合は、想定していた「新しい告知先を必要としている主催者」というユーザー像や、フリマップが提供する価値そのものにニーズがない可能性もあると考え、ターゲットやサービス内容を見直す。

### 懸念点②：不適切な内容の投稿

- **何が問題になりそうか：**
  不適切な投稿が表示されると信頼を失う
- **なぜそう思うか：**
  悪意のある内容が投稿される可能性があるため
- **対策：**
  文字制限など投稿のフィルターを将来的には実装予定

### 10-2. 技術選定の比較検討

地図機能は本サービスの中心となるため、料金や実装難易度だけでなく、
「フリマを探す」と「開催場所を調べる」を一つの体験にまとめるというサービスコンセプトに合っているか、
また、ユーザーが新しい操作を覚えずに直感的に使えるかというUI/UXの観点を重視して比較しました。

| 候補 | 採用/不採用 | 理由 |
| --- | --- | --- |
| Google Maps JavaScript API | 採用 | 本サービスは、「フリマを探す」と「開催場所を調べる」を一つの体験にまとめることを目的としている。そのため、地図自体にも新しい学習コストを発生させず、多くのユーザーが普段から使い慣れているGoogle Mapsの操作感を活かせることを重視した。また、Google Geocoding APIと組み合わせることで、住所から座標への変換と地図表示を同じGoogle Maps Platform内で構成できる点も採用理由とした。 |
| Leaflet + OpenStreetMap（Nominatim） | 不採用 | オープンソースで導入しやすく、費用を抑えやすい点は魅力だと感じた。一方で、地図の見た目や操作感を自分で構成できる自由度が高い反面、今回のサービスでは独自の地図体験を作ることよりも、ユーザーがすでに慣れている地図上でそのままフリマを探せることを優先した。また、地図表示とジオコーディングを別の仕組みとして検討する必要がある点も、今回の構成ではGoogle Mapsより複雑になると判断した。 |
| Mapbox | 不採用 | 地図デザインのカスタマイズ性が高く、独自性のあるUIを作れる点は魅力だと感じた。ただし、フリマップでは地図そのものを独自に見せることよりも、「普段使っている地図と同じ感覚で、そのままフリマを探せる」ことを重視した。そのため、見慣れた操作感を活かせるGoogle Mapsの方がサービスコンセプトに適していると判断した。 |

### 10-3. 技術検証（Google Maps API）
地図機能は本アプリの中核となるため、実装前にテスト用リポジトリを作成し、Google Maps APIおよび関連技術の動作検証を行った。

#### 1. 地図の表示
まずはGoogle Maps JavaScript APIの公式ドキュメントを参考に、地図が正常に表示されるかを検証した。

```html
<gmp-map
  center="35.65861,139.70111"
  zoom="13"
  map-id="DEMO_MAP_ID">
  <gmp-advanced-marker
    position="35.65861,139.70111"
    title="渋谷駅">
  </gmp-advanced-marker>
</gmp-map>
```

座標を変更することで、任意の位置へ地図を表示し、マーカーを配置できることを確認した。

---

#### 2. 住所から緯度・経度を取得する仕組み
イベント情報を地図へ表示するため、住所から緯度・経度を取得する仕組みを検証した。
まず、イベント名・住所・緯度・経度を持つテスト用モデルを作成し、住所のみを登録するフォームを作成した。この時点では、緯度・経度は`nil`で保存されることを確認した。
続いて、Geocoderを導入し、モデルへ以下の設定を追加した。

```ruby
geocoded_by :address
after_validation :geocode
```

また、Railsコンソールでも動作を確認した。

```ruby
results = Geocoder.search("渋谷駅")
results.first.coordinates
#=> [35.658..., 139.701...]
```

検証中には、

```
Google API error:
request denied (API keys with referer restrictions cannot be used with this API.)
```

というエラーが発生した。
原因を調査したところ、Google Geocoding APIで利用するAPIキーの制限設定が原因であったため、適切な設定へ変更することで住所から緯度・経度が自動で保存されることを確認した。

---

#### 3. 地図上へイベントを表示
取得した緯度・経度をGoogle Maps JavaScript APIへ渡し、イベントの位置へマーカーを表示する検証を行った。

```javascript
const marker = new google.maps.Marker({
  position: {
    lat: event.latitude,
    lng: event.longitude
  },
  map: map
});
```

イベントごとに緯度・経度を渡すことで、複数のイベントを地図上へ表示できることを確認した。

---

#### 4. マーカークリック時の情報表示
マーカーにクリックイベントを追加し、イベント情報を表示する機能を検証した。
